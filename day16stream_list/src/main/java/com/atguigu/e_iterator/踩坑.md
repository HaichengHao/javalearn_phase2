这是一个非常好的 Java 基础问题！你问的是：**为什么在比较字符串时要用 `equals()` 而不能用 `==`？**

---

### 简单回答：
- `==` 比较的是**对象的内存地址**（即是否是同一个对象）。
- `equals()` 比较的是**对象的内容**（即字符串的值是否相同）。

---

### 详细解释：

在 Java 中，`String` 是**引用类型**。当你写：

```java
String s1 = new String("猪八戒");
String s2 = new String("猪八戒");
```

虽然 `s1` 和 `s2` 的内容都是 `"猪八戒"`，但它们是两个**不同的对象**，存储在堆内存的不同位置。

- `s1 == s2` → `false`（因为地址不同）
- `s1.equals(s2)` → `true`（因为内容相同）

而在你的代码中：

```java
if ("猪八戒".equals(s)) { ... }
```

这里 `"猪八戒"` 是一个字符串字面量（存在字符串常量池中），而 `s` 是从 `ArrayList` 中取出的元素。虽然它们内容相同，但**不一定指向同一个内存地址**，所以用 `==` 可能返回 `false`，导致判断失败。

---

### 为什么有时候 `==` 也能“碰巧”成功？

Java 有一个**字符串常量池**（String Pool）机制。如果你这样写：

```java
String a = "猪八戒";
String b = "猪八戒";
```

那么 `a == b` 会是 `true`，因为 JVM 会复用常量池中的同一个对象。

但一旦涉及 `new String()` 或从集合、用户输入、文件读取等地方获取的字符串，就**不能保证**是同一个对象了。

---

### 最佳实践：
> **永远用 `.equals()` 来比较字符串内容！**

```java
if ("猪八戒".equals(s)) {  // ✅ 正确
if (s == "猪八戒") {       // ❌ 错误，可能失效
```

另外，把常量 `"猪八戒"` 写在前面（如 `"猪八戒".equals(s)`）还能避免 `s` 为 `null` 时抛出 `NullPointerException`，是一种更安全的写法。

---

### 补充：你的代码还有一个问题 ⚠️

你在遍历 `ArrayList` 的同时调用 `lst.add("白龙马")`，这会抛出 `ConcurrentModificationException`！因为 Java 的增强 for 循环（for-each）底层使用迭代器，不允许在遍历过程中修改集合结构。

✅ 正确做法是使用 `ListIterator`：

```java
ListIterator<String> it = lst.listIterator();
while (it.hasNext()) {
    String s = it.next();
    if ("猪八戒".equals(s)) {
        it.add("白龙马"); // 安全插入
    }
}
```
